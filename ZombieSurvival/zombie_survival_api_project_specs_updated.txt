ZOMBIE SURVIVAL API
Text-Based Survival Game
ASP.NET Core / C# Backend Project

PROJECT VISION
Build an original, text/API-driven zombie survival game inspired by classic day-scavenge / night-defense survival games (e.g. the general loop popularized by browser games like The Last Stand), reimagined for a modern ASP.NET Core backend.

This is NOT an open-world video game.
This is NOT a one-to-one recreation of The Last Stand or any other existing game.

Tone and structure:
- Side-view / stage-based survival-defense DNA (actions via API, not Flash/Unity graphics)
- Campaign progress across the United States by major city
- Day: scavenge local areas for supplies
- Night: fight off zombies
- Goal: keep yourself and your car alive long enough to reach New York

Use original names, story details, weapons, enemies, and mechanics.

The project is intentionally backend-focused. No 3D graphics, Unity, or complicated frontend is required. Swagger or Insomnia can be the initial interface.

Core technologies:
- C#
- ASP.NET Core Web API
- Entity Framework Core
- SQL Server
- Custom middleware
- REST APIs
- Swagger/OpenAPI

Advanced features can be added later:
- Background services
- Transactions
- Concurrency
- Rate limiting
- Caching
- Health checks
- API versioning
- Optional authentication (Identity + JWT) if cloud saves / accounts are ever needed

==================================================
1. GAME CONCEPT
==================================================

The player is a survivor trying to cross a zombie-infested United States by car.

Main objective:
Start in Los Angeles and travel major-city to major-city until reaching New York. Reaching New York wins the game.

Route (v1) — MUST be completed IN ORDER (no skipping cities):
Los Angeles -> Phoenix -> Dallas -> Chicago -> New York

Each major city is a hub with local areas you can enter to scavenge (gas stations, gun stores, grocery stores, churches, etc.).

You need:
- Food / water to stay alive
- Guns / ammo for night defense
- Fuel to refill the tank after each city hop (tank is empty on arrival)
- Car parts to repair wear and tear from each city hop

Key rules:
- Cities are unlocked only in route order (cannot go Dallas before Phoenix, etc.)
- Arriving in a new city empties the gas tank AND applies car wear and tear (Condition drops)
- Daytime must be spent refueling AND finding car parts to repair before the next city travel
- Each night spent in the same city makes that city's nights harder
- The same area can be looted again on a later day/night cycle, but NOT twice on the same day (same daylight period)

Core loop:

HIT PLAY
  -> Create or select a save (later; for now create a player)
  -> Start in Los Angeles (tank may start with some fuel, or empty — pick one and stay consistent)
  -> Travel between areas in the current city
  -> Scavenge during the day (burns stamina; costs depend on area; each area once per day)
  -> Prioritize gas stations (fuel) and areas that yield car parts
  -> When stamina is exhausted, night falls
  -> Defend against zombies (harder the longer you have stayed in this city)
  -> At dawn, areas can be scavenged again; recover and prepare
  -> Refill fuel AND repair Condition with car parts
  -> When fueled and repaired enough, travel ONLY to the next city on the route
  -> On arrival: gas tank empty again + fresh wear and tear; repeat
  -> Reach New York -> WIN

The front door is NOT register/login. The player opens the game, hits play, and (later) chooses or creates a save.

The game should be simple enough to build without a graphics engine, but deep enough to create meaningful C# and backend logic.

==================================================

The world is NOT a free-roam open map. It is a directed campaign of cities and areas.

CITY (route hub)
- Id
- Name
- Description
- RouteOrder (1 = Los Angeles ... last = New York)
- IsWinCity (true for New York)

V1 cities:
1. Los Angeles
2. Phoenix
3. Dallas
4. Chicago
5. New York (win)

AREA (scavenge location inside a city)
- Id
- CityId
- Name
- Description
- AreaType
- DangerLevel
- ScavengeStaminaCost
- LootProfile (optional / later)

Example area types:
- GasStation
- GunStore
- GroceryStore
- Church
- SafeRest (starting / low-danger rest spot in a city)

Example areas in Los Angeles:
- Outskirts Rest Stop
- Corner Gas Station
- Valley Grocery
- Pawn & Gun
- Neighborhood Church

TRAVEL has two meanings:
1. Area travel — move between areas inside the current city
2. City travel — advance ONLY to the next RouteOrder city (requires enough fuel; no skipping)

City travel rules:
- Destination must be current RouteOrder + 1 (strict order)
- Fuel must meet the departure requirement
- Condition must meet the minimum roadworthiness requirement
- On successful arrival:
  - set Fuel = 0 (tank empty)
  - apply wear and tear (reduce Condition by a fixed or city-scaled amount)
  - player must refill AND repair in the new city before the next hop
- Set LocationId to the new city's default rest area
- If new city.IsWinCity -> player has won

Possible endpoints:
POST /api/travel/area
POST /api/travel/city
GET  /api/cities
GET  /api/cities/{id}/areas

==================================================
4. CAR / ROAD TRIP PROGRESSION
==================================================

The car is what makes the campaign move east.

Car (v1 can be fields on Player, or a separate Car entity):
- Fuel (0 = empty tank)
- FuelCapacity (e.g. 100)
- Condition (0–100; roadworthiness — drops from travel wear and tear)
- PartsInventory (via items) — used to restore Condition

Fuel rules:
- Leaving for the next city consumes the trip fuel requirement (or simply requires tank to be full)
- On ARRIVAL in a new city, Fuel is set to 0 — the tank is empty
- The player must use daytime scavenging (especially GasStation areas) to refill before the next city travel

Wear and tear / car parts rules:
- Every successful city hop applies wear and tear (e.g. Condition -= 15, or scaled by distance/city)
- Condition too low blocks the next intercity travel even if the tank is full
- Scavenge car parts (GasStation and similar) and spend them to repair Condition (e.g. use item -> Condition up)
- Both Fuel AND Condition must be ready before departing for the next city

Cannot skip ahead on the route even if fueled and repaired.

Intercity travel rules:
- Player must be in Day phase
- Destination must be the next city only (RouteOrder + 1)
- Fuel must meet the departure requirement (e.g. full tank, or >= trip cost)
- Condition must meet the minimum threshold
- Move CityId to that next city; reset NightsInCurrentCity to 0
- Set Fuel = 0 on arrival
- Apply wear and tear to Condition on arrival (or on departure — pick one and stay consistent; arrival is recommended)
- Set LocationId to the new city's default rest area
- Clear AreasAlreadyScavengedToday
- If new city.IsWinCity -> player has won

Failing to refill or repair strands the player in the current city (surviving harder nights) until they gather enough fuel and parts.

==================================================
5. DAY / NIGHT CYCLE
==================================================

DAY
- Player may travel between areas in the current city
- Player may scavenge; each scavenge burns stamina based on the current area
- An area may be scavenged at most ONCE per Day
- Same area may be scavenged again after dawn (a new Day)
- Player scavenges until stamina is too low for another action
- Refilling the gas tank AND repairing wear and tear with car parts are primary daytime goals after arriving

NIGHT
- Triggered when stamina cannot support another scavenge, or via an explicit end-day action
- Increment NightsInCurrentCity when night begins (or when night is survived — pick one and stay consistent)
- Spawn a zombie encounter scaled by:
  - Base city/area DangerLevel
  - PLUS escalation from NightsInCurrentCity (each extra night in the same city is harder)
- Player fights (attack / flee) until the wave is cleared or the player dies

DAWN
- Return to Day
- Restore some or all stamina
- Clear AreasAlreadyScavengedToday so areas can be looted again
- Optionally increase hunger/thirst pressure
- Ready to scavenge (including reloot), refill fuel, or attempt next-city travel if fueled

8. SCAVENGING
==================================================

Example:
POST /api/scavenge

The server determines:
1. Current city and area
2. Whether it is Day
3. Whether this area was already scavenged today (if yes -> reject; try again after dawn)
4. Whether the player has enough stamina for this area's ScavengeStaminaCost
5. What loot/event occurs (weighted by AreaType)
6. What resources are consumed (stamina; later hunger/thirst)
7. Mark area as scavenged for this Day
8. What gets persisted
9. Whether night should begin (stamina exhausted)

Same-area rule:
- Cannot scavenge the same area twice in one Day
- After dawn, that area is available again (reloot across different nights/days is allowed)

Loot focus by area type (v1):
- GroceryStore -> food / water
- GunStore -> weapons / ammo
- GasStation -> fuel (refill empty tank) AND common car parts (repair wear and tear)
- Other areas may rarely drop parts; gas stations are the reliable source
- Church -> small food / lower danger / light supplies

Possible events:
- Nothing useful
- Food / water
- Weapon / ammo
- Car part / fuel
- Small medical find
- Ambush (optional later)

The game logic belongs primarily in services/domain logic, not controllers.

10. COMBAT (NIGHT DEFENSE)
==================================================

Combat is action/turn based rather than real-time.
This is night defense, not open-world encounter roaming.

Endpoint:
POST /api/combat/{encounterId}/attack

Basic flow:
Weapon damage (or unarmed default)
  -> Accuracy
  -> Hit/miss
  -> Critical hit?
  -> Zombie defense
  -> Final damage
  -> Update health

Example response:
{
  "action": "Attack",
  "weapon": "9mm Pistol",
  "result": "Hit",
  "damage": 27,
  "critical": false,

  "zombieHealth": 23
}

15. CUSTOM MIDDLEWARE
==================================================

Implement at least three custom middleware components.

A. GLOBAL EXCEPTION HANDLING
Controller

  -> Exception middleware catches it
  -> Consistent HTTP response

Example:

  "statusCode": 404,

B. CORRELATION ID MIDDLEWARE

27. END GOAL
==================================================

The finished application should be a playable text/API-driven survival campaign.

A typical session could look like:

HIT PLAY
  -> Create survivor (name only) in Los Angeles
  -> Travel to Valley Grocery
  -> Scavenge (food, stamina down) — cannot loot Valley Grocery again until dawn
  -> Travel to Pawn & Gun
  -> Scavenge (ammo)
  -> Stamina depleted -> night 1 in LA (baseline difficulty)
  -> Defend against walkers
  -> Dawn (areas available again)
  -> Scavenge Gas Station for fuel AND car parts
  -> Repair Condition; refill tank
  -> Night 2 in LA is harder than night 1 if still stuck
  -> When fueled and repaired, travel ONLY to Phoenix (not Dallas)
  -> Arrive in Phoenix: empty tank + Condition reduced from the trip
  -> Repeat pattern through Dallas and Chicago
  -> Reach New York
  -> WIN

Every action is handled through the ASP.NET Core backend.

The game should be fun enough to keep developing while providing meaningful practice with C# and the ASP.NET Core ecosystem.
