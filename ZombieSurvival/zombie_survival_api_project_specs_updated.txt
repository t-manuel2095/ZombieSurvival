ZOMBIE SURVIVAL API
Text-Based Survival Game
ASP.NET Core / C# Backend Project

PROJECT VISION
Build an original, text/API-driven zombie survival game inspired by the general survival, scavenging, combat, exploration, progression, and resource-management concepts found in zombie survival games.

This is NOT a one-to-one recreation of The Last Stand or any other existing game.

Use original names, world, characters, weapons, locations, enemies, missions, story, and mechanics.

The project is intentionally backend-focused. No 3D graphics, Unity, or complicated frontend is required. Swagger can be the initial interface.

Core technologies:
- C#
- ASP.NET Core Web API
- Entity Framework Core
- SQL Server
- JWT authentication
- Authorization
- Custom middleware
- REST APIs
- Swagger/OpenAPI

Advanced features can be added later:
- Background services
- Transactions
- Concurrency
- Rate limiting
- Caching
- Health checks
- API versioning

==================================================
1. GAME CONCEPT
==================================================

The player is a survivor in a zombie-infested world.

The player travels between locations, searches for supplies, encounters zombies and other survivors, fights, collects equipment, completes missions, improves their safehouse, and tries to stay alive.

Example flow:

LOGIN
  -> View character
  -> Travel to location
  -> Scavenge
  -> Find loot / survivor / zombie encounter
  -> Combat
  -> Collect rewards
  -> Return to safehouse
  -> Upgrade / resupply
  -> Accept another mission

The game should be simple enough to build without a graphics engine, but deep enough to create meaningful C# and backend logic.

8. COMBAT
==================================================

Combat is action/turn based rather than real-time.

Endpoint:
POST /api/combat/{encounterId}/attack

Basic flow:
Weapon damage
  -> Accuracy
  -> Hit/miss
  -> Critical hit?
  -> Zombie defense
  -> Final damage
  -> Update health

Example response:
{
  "action": "Attack",
  "weapon": "9mm Pistol",
  "result": "Hit",
  "damage": 27,
  "critical": false,
  "ammoRemaining": 11,
  "zombieHealth": 23
}

15. CUSTOM MIDDLEWARE
==================================================

Implement at least three custom middleware components.

A. GLOBAL EXCEPTION HANDLING
Controller
  -> Service throws exception
  -> Exception middleware catches it
  -> Consistent HTTP response

Example:
{
  "statusCode": 404,
  "message": "Player not found.",
  "traceId": "abc123"
}

B. CORRELATION ID MIDDLEWARE
Every request receives a correlation ID.

Example:
X-Correlation-ID: 8f7c2a...

C. REQUEST LOGGING MIDDLEWARE
Log:
POST /api/combat/42/attack
User: 123
Status: 200
Duration: 38ms
CorrelationId: 8f7c2a

Never log passwords, JWT tokens, or other sensitive information.

17. TRANSACTIONS
==================================================

A zombie kill may require:
1. Update zombie
2. Award XP
3. Level up player if necessary
4. Generate loot
5. Add loot to inventory
6. Record combat history
7. Update mission progress

These operations should succeed together.

Use EF Core/database transactions where appropriate.

18. CONCURRENCY
==================================================

Example:
A rare item is available.
Two requests arrive almost simultaneously.

Request A -> claims item

Prevent invalid duplicate state.

- Transactions
